# wh-storage-service — Agent Instructions

Go (chi) service. Warehouse storage management on schema `"Storage"`.

## Build & Run

```bash
go mod tidy && swag init
go run main.go -env local
```

Config: `application_<env>.json` (`secretkey`, `database`, `state`, `jwt`, `log`).

## DB Migration & Seeding

Custom runner, no external deps. Subcommands after flags (default = serve):

```bash
go run main.go -env local migrate up        # apply pending migrations
go run main.go -env local migrate down [n]  # rollback last n (default 1)
go run main.go -env local migrate status    # applied/pending per migration
go run main.go -env local seed [name]       # all seeders, or one by name
```

- `migration/` — registry of `Migration{Version, Name, DBKey, Up, Down}`; `Version` is a `string` (timestamp-style, e.g. `"202611130001"` — sorts lexicographically) stored as `VARCHAR(32)` in `storage_schema_migration` (auto-created per DB). Each file registers via `init()` and declares its target `DBKey` from `cfg.Database` (writer, never replica). New migration = new file `migration/<version>_<name>.go`. Currently registered: `202611130001` (`create_storage_schema_tables`).
- `seed/` — registry of `Seeder{Name, DBKey, Run}`; seeders must be idempotent (`ON CONFLICT DO NOTHING`). Currently registered: `storage_status`.
- Makefile shortcuts: `make migrate-up migrate-down migrate-status seed` (`ENV=`, `STEPS=`, `NAME=`).

## Routes (`app/controller/controller.go`)

- `/ping`, `/health/check`, `/health/check-db`; `/swagger` non-prod
- Storage slice (`storage_handler.go` / `storage_service.go` / `storage_repository.go` + `query/storage_queries.go`) on `"Storage".storage`, under `/storage`:
  - `POST /storage` — `StorageCreate` (uid DB-generated via `RETURNING`; `StorageRequest`: `name`, `goods_uid`, `warehouse_id`, `block_id`, `status`, `x_row`, `y_row`)
  - `GET /storage` — `StorageGetAll`; `GET /storage/{uid}` — `StorageGetByID` (reads replica)
  - `PUT /storage/{uid}` — `StorageUpdate`; `DELETE /storage/{uid}` — `StorageDelete`
- Lookup slice `storage_status` (`storage_status_*`) on `"Storage".storage_status`, under `/storage/status`:
  - `POST /storage/status` — create `{name}` → `RETURNING id` (identity); `GET /` list; `GET|PUT|DELETE /{id}`
- Warehouse slice (`warehouse_*`) on `"Storage".warehouse`, under `/warehouse`:
  - `POST /warehouse` — `WarehouseCreate` → `RETURNING id` (`WarehouseRequest`: `name`, `code`, `address`, `ttl_area`); `GET /` list; `GET|PUT|DELETE /{id}`
- Block layout slice (`block_layout_*`) on `"Storage".block_layout`, under `/block-layout`:
  - `POST /block-layout` — `BlockLayoutCreate` → `RETURNING id` (`BlockLayoutRequest`: `warehouse_id`, `block_name`, `floor`, `x_sum`, `y_sum`); `GET /` list; `GET|PUT|DELETE /{id}`

chi static segments (`status`) win over `{uid}` — no route conflicts. All slices: create → 201, get/update/delete → 200, not found → 404; audit cols `created_by`/`updated_by` filled with `service_name` by repo.

## Databases & Clients

- Single Postgres DB `warehouse_db` — no replica (writer key reused for reads). Schema `"Storage"` holds `storage`, `storage_status`, `block_layout`, `warehouse`. Lookup/entity `id` columns are `GENERATED BY DEFAULT AS IDENTITY` — seeders may still insert explicit ids.
- Repositories keep the writer+replica signature (`db` + `dbReplica`); `main.go` passes `warehouse_db` for both.
- No Redis client is used by this service.

## Schema `"Storage"`

```sql
CREATE TABLE "Storage".storage_status (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(32) NOT NULL, -- +audit cols
);
CREATE TABLE "Storage".warehouse (
    id       INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name     VARCHAR(64) NOT NULL,
    code     VARCHAR(32) NOT NULL,
    address  TEXT,
    ttl_area INT,
    -- +audit cols
);
CREATE TABLE "Storage".block_layout (
    id           INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    warehouse_id INT NOT NULL REFERENCES "Storage".warehouse (id),
    block_name   VARCHAR(32) NOT NULL,
    floor        VARCHAR(32),
    x_sum        INT,
    y_sum        INT,
    -- +audit cols
);
CREATE TABLE "Storage".storage (
    uid          VARCHAR(16) PRIMARY KEY
                DEFAULT upper(substr(md5(random()::text), 1, 16)),  -- DB-generated uid
    name         VARCHAR(16) NOT NULL,
    goods_uid    VARCHAR(16),   -- loose ref to goods.uid, no FK
    warehouse_id INT NOT NULL REFERENCES "Storage".warehouse (id),
    block_id     INT NOT NULL REFERENCES "Storage".block_layout (id),
    status       INT NOT NULL REFERENCES "Storage".storage_status (id),
    x_row        INT,
    y_row        INT,
    -- +audit cols
);
```

Audit columns on every table: `created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`, `created_by VARCHAR(64)`, `updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`, `updated_by VARCHAR(64)`. Nullable columns map to pointer fields in entities (`*string`, `*int`).

- `storage.goods_uid` intentionally has no FK — goods is owned by a different service. Add an `ALTER TABLE` migration if a hard FK is needed.
- Seeded lookups (placeholder values, adjust in `seed/`): `storage_status` (Empty/Occupied/Maintenance).
